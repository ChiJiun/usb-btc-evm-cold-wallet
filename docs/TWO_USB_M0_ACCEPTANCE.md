# Two-USB M0 exact-image / physical acceptance (#1, #43, #66)

**Scope:** USB-A = x86_64 UEFI Buildroot OS + `COLD_VAULT` (two GPT partitions); USB-B = independent FAT32 `TX_TRANSFER`. This is the **two-device M0 CLI/text appliance**, not PR #80's single-USB three-partition/GUI acceptance. Use only public/expendable test wallet and testnet funds. No signer, vault, runtime, CI, flash or format automation is provided here.

**Current record:** all cases **NOT TESTED** until a named tester supplies actual observations. M0 **BLOCKED**. Never substitute a historical CI result or QEMU boot for final image-byte or physical acceptance. Never include mnemonic, passphrase, private key, vault bytes, full sensitive payload, unredacted serial or policy anchor secret in evidence.

## A. Exact source → image / kernel provenance (Linux x86_64)

From a **clean** checkout of the *selected integration/source commit* (record the SHA, not just `main`), verify commands exist with `test -f Makefile && test -x scripts/verify_uefi_boot.sh && test -x scripts/verify_image.sh`. Run and preserve stdout/stderr and exit codes:

```sh
git status --porcelain
git rev-parse HEAD
make prepare-sources
make image
make verify
sha256sum build/output/images/usb-cold-wallet.img build/output/images/bzImage
(cd build/output/images && sha256sum -c usb-cold-wallet.img.sha256 && sha256sum -c bzImage.sha256)
make reproducibility-check
cmp build/reproducibility/run-1.sha256 build/reproducibility/run-2.sha256
make verify
scripts/verify_uefi_boot.sh
sha256sum build/output/images/usb-cold-wallet.img build/output/images/bzImage
```

`make reproducibility-check` **deletes generated `build/output` and builds twice** in the same output path; run only on a disposable build workspace with no local artifacts to preserve. It compares image and kernel hashes, and the **final generated bytes** must be reverified afterward. Save both `build/reproducibility/run-{1,2}.sha256`, CI job URLs, source SHA, build host architecture, tool versions, actual digest values and the SHA-256 of any downloaded artifact. This is two sequential local clean builds; #88's **separate-runner parallel clean-build equality / Required gate** is an additional CI assertion and must not be replaced by the local check. The mere existence of `.sha256` files proves nothing about downloaded artifact authenticity.

QEMU/OVMF: install the host `qemu-system-x86_64` plus a matching OVMF CODE/VARS pair; run `scripts/verify_uefi_boot.sh` from repository root after producing the **same final image**. The script uses a disposable variables store, `-net none`, snapshot USB disk and demands serial `USB_WALLET_UEFI_AUDIT_OK`; `USB_WALLET_UEFI_AUDIT_LOCKDOWN`, timeout or premature exit is FAIL. The script does **not** test interactive transactions, USB-B or physical boot. Save the command exit code, console output, tool/firmware versions, image hash and bounded diagnostic path `build/reproducibility/uefi-smoke.log` (written on failure). Only claim CI evidence for a run that identifies the tested source and image bytes, with matching hash artifact.

**Artifact blocker:** a checksum-only CI artifact cannot be flashed. Require exact raw `.img` bytes from an authenticated build or a trusted, separately hashed, reproducible local build; verify both the expected digest and the file actually flashed. Do not equate a digest in an untrusted download bundle with trusted provenance.

## B. Two physical media, Windows and offline operator sequence

1. On the Windows host, identify both physical devices with PowerShell `Get-Disk`, `Get-Partition`, `Get-Volume` (and `Get-FileHash -Algorithm SHA256 <image-path>` for the **local raw file only**). Confirm model, capacity, bus, sector size, partitions and device ancestry on **each insertion**; no fixed PhysicalDrive number or drive letter. PR #80's `scripts/physical_usb_inventory.ps1` is available on **its PR branch only**, not assumed present on current main/#85. Never use its single-USB partition expectations for M0.
2. A human operator, after positive hardware identification and backup, uses a trusted GUI imaging application to write the verified image to **USB-A** (erases USB-A). Capture application readback result and independently audit actual GPT/ESP/`COLD_VAULT` on **written media**; the host raw-file SHA by itself does not validate flashed media. Provision **USB-B** as FAT32 volume label `TX_TRANSFER` separately, only after confirming its physical parent differs. This document intentionally supplies **no destructive flash/format commands**.
3. Boot USB-A on a real x86_64 UEFI host with USB-B attached. Record exact firmware/version/Secure Boot setting, cold boot timing and startup audit. Inspect `/proc/mounts`, `/proc/swaps`, `/proc/net`, resolved kernel config, unique PARTUUID ancestry and lockdown status using read-only appliance/runtime facilities. Expect RAM-only root, no networking/swap, restricted vault mount, no unintended writable internal drive; a failure must forbid signing. Preserve redacted audit transcript, not a claimed PASS based on seeing a menu.
4. Create/recover the encrypted vault with a **public test seed** and establish policy + independently trusted policy-hash anchor using the appliance's current menu; reboot to verify vault persists, wrong password denies and prior lock states do not silently roll back. Never put the anchor secret or seed in report files.
5. **Windows → USB-B → offline signer → USB-B → Windows, Sepolia:** use the *checked-out* Companion's documented command/GUI, record the actual syntax from its help, create a type-2 **native** transfer on `chainId=11155111`. Record a sanitized request ID/digest; on the cold text appliance independently review account, recipient, value, nonce, gas limit and maximum fee before explicit approval. Import the signed response online; verify account, chain, request binding, transaction fields and recovered signer. Broadcast only after separate deliberate user authorization; record tx hash and receipt only if actually broadcast.
6. Repeat the round trip for **Bitcoin testnet BIP84 PSBT v0**. Cold side checks network, account, UTXOs, recipient, change, amount and absolute fee before manual sign. Online side verifies the signed response, signatures and original PSBT semantics, finalizes/extracts if supported; only explicit user broadcast produces a recorded txid. Record unsigned PSBT digest and request ID, never fabricate a txid if no broadcast occurred.
7. For negative cases use **reproducible, disposable** test media only. Test USB-A/B swap, wrong parent, duplicate label or PARTUUID, wrong partition, malformed/truncated request, altered recipient/amount/chain/account, wrong policy anchor, replay after reboot, USB-B removal and interruption during request/response/vault writes as **separate cases**. Observe fail-closed effects and absence of unauthorized signature/broadcast. Restore from known clean test state between injections; do not infer anti-rollback from authenticated encryption or USB file metadata.

For real commands, record precisely what `usb-cold-wallet --help` and the installed Companion version expose on the **tested commit**; an unrun placeholder is not an executed command. Avoid copying PR #80's single-USB reboot/GUI steps into this two-USB acceptance.

## C. Evidence schema and strict decision rules

Store redacted evidence off both USB devices (e.g. local `evidence/two-usb-m0/<run-id>/`); store **no seed, vault, secrets, unredacted serial or raw private transaction payload**. Every **atomic case**, including negative injections, has an independent record containing all required fields:

```json
{
  "schema_version": 2,
  "mode": "two-usb-m0",
  "source_commit": "",
  "image_sha256": "",
  "kernel_sha256": "",
  "ci_run_urls": [],
  "host": {"architecture": "", "uefi_vendor_version": "", "secure_boot": null},
  "usb_a": {"model": "", "capacity_bytes": null, "logical_sector_bytes": null},
  "usb_b": {"model": "", "capacity_bytes": null, "logical_sector_bytes": null},
  "cases": [
    {
      "id": "EXACT_IMAGE",
      "environment": "CI/x86_64",
      "status": "NOT TESTED",
      "command_or_operator_action": "",
      "expected_result": "Trusted source, two-build image and kernel equality; verified final raw image",
      "observed_result": "",
      "exit_code": null,
      "request_id": null,
      "transaction_id": null,
      "artifact_sha256": null,
      "evidence_paths": [],
      "security_decision": "",
      "notes": ""
    }
  ]
}
```

Populate **one independent record for EACH case ID below** (same fields; keep status `NOT TESTED` and observation/evidence empty until tested):

| Case IDs | Expected evidence / rejection behavior |
| --- | --- |
| EXACT_IMAGE, IMAGE_GPT_KERNEL, QEMU_OVMF | SHA-256 and final bytes, GPT/config verifier, QEMU audit exit + logs |
| USB_A_READBACK, USB_B_FAT32_ID, UEFI_PHYSICAL_BOOT, OFFLINE_ISOLATION | media ancestry/readback, volume label, actual UEFI boot, mount/network/swap/audit |
| VAULT_POLICY_REBOOT, BTC_REQUEST, BTC_COLD_REVIEW, BTC_SIGN, BTC_IMPORT_VERIFY | vault persistence, PSBT request/review/signed response/binding evidence |
| SEPOLIA_REQUEST, SEPOLIA_COLD_REVIEW, SEPOLIA_SIGN, SEPOLIA_IMPORT_VERIFY | type-2 request/review/signature/recovered address + binding |
| BTC_BROADCAST, SEPOLIA_BROADCAST | separate optional manual broadcast + txid/receipt; no broadcast remains NOT TESTED |
| USB_SWAP, WRONG_MEDIA_PARENT, WRONG_PARTITION, DUPLICATE_PARTUUID, MALFORMED_REQUEST | independently observed rejection/lockdown with no signature |
| ALTERED_TRANSACTION, WRONG_CHAIN_ACCOUNT, WRONG_POLICY_ANCHOR, REPLAY_REQUEST, REPLAY_RESPONSE | signed-content mismatch rejection / verified trusted replay state |
| USB_B_UNPLUG, POWER_LOSS_REQUEST, POWER_LOSS_RESPONSE, POWER_LOSS_VAULT, RECOVERY | each physical failure injection and recovery outcome separately |

- **PASS**: actual action executed on identified environment/image, observed outcome matches expected security invariant, exit code (when applicable), SHA/request/tx identifier when applicable, at least one **existing, inspectable** evidence path and explicit security decision. A planned command, nonempty free-text claim or CI success with no image identity is insufficient.
- **FAIL**: executed case violates expected behavior. Include redacted observed behavior, failure stage and evidence.
- **BLOCKED**: could not execute because a specific prerequisite is absent (identify missing raw image, funds, trusted replay anchor, hardware, incompatible firmware, etc.); no claim of successful execution.
- **NOT TESTED**: not attempted, or no verifiable execution evidence. All physical hardware cases start and remain here until physical observations exist. A PR CI run can only support CI-scoped cases on matching source/image bytes.
- Report coverage as **verified PASS / total required cases**, and separately **executed / total**; optional broadcast tests must be counted separately, not silently removed from denominator. No aggregate PASS if a required case is FAIL/BLOCKED/NOT TESTED.
